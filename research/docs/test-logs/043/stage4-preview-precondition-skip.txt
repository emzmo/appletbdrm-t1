# Stage-4 preview precondition check — RESULT: SKIP (precondition FALSE)
# Session 043

## precondition (from runbook)
"verify from CURRENT code (cite file:line) that no default-page widget action
performs uinput key injection. If ANY doubt → SKIP. If clean: during the STEP 7
window, ask the human to touch the bar once; confirm the journal shows the tap
log ... and NOTHING else happens (no injection, no desktop effect)."

## code-derived verdict (read-only audit)
The precondition is FALSE. The default-page widgets ARE armed to inject keys
via uinput. SKIP the Stage-4 preview.

- `src/main.rs:786-802` — Gesture::Tap arm:

## why no injection occurred in HC2 (safety depended on a DEFECT)
The input-path defect (finding (a)/Fact 2) dropped the touch before it reached
the gesture handler (current_bl==0 gate at src/providers/input.rs:471). So no
Gesture::Tap was ever recognized, and emit_keys was never called. The widgets
are ARMED to inject; the only reason they didn't is that the touch was dropped
upstream. The safety of the Stage-4 preview depended on the input-delivery
defect holding — which is NOT a safe basis for a preview.

## verdict
Stage-4 preview: SKIPPED. Precondition ("no default-page widget action performs
uinput key injection") is FALSE. Every default-page widget is a key-emitting
ButtonWidget. The HC2 "single bright widget mark on the left side" is the
auto-added `esc` button (action=[Key::Esc], src/main.rs:1141-1145) — touching
it WOULD inject Esc via uinput if the touch reached the handler.

Stage 4 owes (before preview is safe):
  1. Fix the input-path defect (current_bl==0 gate + notify_activity wiring)
     so touches reach the gesture handler — ADR-047 (proposed, finding (a)).
  2. Re-verify the tap log appears (info! at src/main.rs:786) AND no UNEXPECTED
     injection occurs. NOTE: the default page's OWN widgets inject Esc/F-keys
     by design — so "no injection" is only true for a RENDER-ONLY page, not the
     default page. A Stage-4 preview would need a render-only page config (no
     key actions) OR explicit acknowledgment that the default page injects by
     design. The runbook's "no injection, no desktop effect" criterion cannot
     be met with the default page.
  3. Cross-check the raw event shape against the corpus (already done in this
     session — docs/test-logs/043/input-diagnostic-finding-a.txt — the kernel-
     side event shape matches single-tap.evdev; the tbard-internal side of the
     chain is NOT yet verified on hardware).

This finding does NOT block Stage-3 acceptance (Stage 3 is render-only; the
input path was always Stage-4 territory). It DOES block the Stage-4 preview.
